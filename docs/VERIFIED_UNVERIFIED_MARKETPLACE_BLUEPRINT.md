## 1. Product goal
Let Nigerian students and tenants discover rental opportunities even while Lodgist has zero Lodgist-verified houses. Never imply that a property has been reviewed when it has not. Separate browse/discovery from proof, contact, booking, and payment.

## 2. Four distinct record types and states
1. VERIFIED LISTING: Real property submitted/authorized for publication, checked against documented evidence by an authorized Lodgist reviewer; record who verified, when, which evidence categories passed, and last reconfirmation. A trust score by itself MUST NOT promote an item to VERIFIED. Only eligible for confirmed booking flows if availability and contact rights are validated.
2. UNVERIFIED LISTING: Real property with explicit contributor/owner authorization or permitted syndication, plus provenance, consent to display media, last-checked date, and clear "Not verified by Lodgist" label. No inferred trust badge. CTA defaults to "Request verification" / "Ask about this property", not guaranteed availability or automatic confirmed booking.
3. DISCOVERY POINTER: A link to an external listing with rights-compliant summary metadata only where authorized. Display source name, destination URL, freshness, attribution and "External listing — not independently checked". Do not host external photos, descriptions, phone numbers, or full inventory without permission. Redirect out; do not issue Lodgist booking or payment on it.
4. AREA EXPLORER / DEMO: When ZERO real listings qualify, show helpful campus/area guides, distance tools, neighborhood exploration and clearly marked illustrative sample cards. No fabricated address, landlord, availability, price quote, ratings, real property pin, or booking CTA. Sample cards never enter the public Listing table or search API as real offers.

## 3. Current model evidence and migration strategy
Prisma already has Listing.status (PENDING/VERIFIED/REJECTED/ARCHIVED), nullable Listing.riskState (VERIFIED/UNVERIFIED/UNDER_REVIEW/FLAGGED/SUSPENDED), Listing.reviewStatus, evidenceVerified, verifiedAt, verifiedById, VerificationRequest and TruthIndex fields.
CAUTION: status=VERIFIED and riskState=VERIFIED do not by themselves prove a completed Lodgist evidence check; public badge must also require audit-backed evidenceVerified === true, eligible publication review status, valid source/consent and no flag/suspension. Inspect all existing publication/viewing predicates before changing anything. Do not re-purpose Listing.status solely for verification without compatibility review: current workflows also use it as a viewing/publication gate. Proposal: introduce a narrowly scoped provenance/discovery model or fields only after reading migrations, API consumers, search predicates, and performance impact.
Separate (a) publication moderation, (b) evidence verification, (c) source/provenance, and (d) live availability. Record transitions atomically with audit trail.

## 4. UX rules (mandatory)
- Search and home: dual sections "Verified by Lodgist" and "More places to explore — not verified"; empty verified section can say "No verified homes in this area yet" with a visible subscribe/waitlist action.
- If all inventories are empty, show "Explore Owerri near FUTO/IMSU" and other supported campuses with sourced area facts, filters, map preview and request-a-property intake. No fake listings.
- Listing card: explicit text status + accessible icon, price and total move-in cost only if provided/verified for that source, last verified/updated date, source and location precision disclosure.
- Detail: "What we checked / What we haven't checked"; CTA appropriate to trust/source; explain that neighborhood context is not a personal safety score.
- Review badges must never be generated by visual design, AI score, or payment; they're derived server-side from documented verification state.
- Sensitive exact locations, owner documents, phone numbers, IDs and private data protected and not exposed to map previews or search indexes.

## 5. Verification funnel
1. Owner/agent submits with authorization, listing details, right-to-publish media, source identity and contact consent.
2. Listing enters moderation / UNVERIFIED (if publishable under policy).
3. Request documents, verify ownership or right to let, identity/authority, address existence, photos/availability and fee transparency; avoid promising certification of ownership absent evidence.
4. Reviewer approves/rejects with a signed/audited action and date; only then evidenceVerified true and server-issued "Verified by Lodgist".
5. Set expiration/recheck policy; downgrade on adverse evidence, stale availability, impersonation or complaints.
6. Never accept payment or confirm a viewing as guaranteed merely because a listing appears in discovery.

## 6. Supply and legal sourcing (critical)
- First-party landlord/student accommodation outreach, authorized agents, user-submitted leads and explicit syndication agreements are preferred.
- Use public portal market statistics and licensed neighborhood context for area pages. Market data permission does NOT imply listing/image republication permission.
- Nigeria Property Centre Terms (updated 2026-10-15) restrict automated software viewing except defined Market Data and prohibit copying listings without consent. Do not scrape/copy listings or media there for Lodgist's inventory.
- PropertyPro or other portal inventory requires provider-specific terms/permission review; attribution alone is not permission.
- For every item keep source, license/permission record, first seen, checked_at, expiry, source URL, dedupe key and takedown contact.
- No copied third-party datasets/images from God's Eye View without separately clearing each provider's terms.

## 7. Spatial Lab integration boundary
Standalone repo: SHADOWSPARK-TECHNOLOGIES/spatial-lab. Lodgist consumes versioned, privacy-preserving area-context contract only; public/campus area focus, snapped approximate location, amenity provenance, straight-line metric explicitly labelled. No surveillance, tracking people, CCTV or exact housing coordinates by default.
Known Lodgist PR #53 merged 2026-10-10, but live map tiles/OSRM/amenity providers were not verified enabled; no unapproved defaults to public OSM tile servers, OSRM demo or Overpass instances. Provider key must remain server-side. Evaluate API terms before enabling any live service.
God's Eye View upstream code MIT; its third-party data, 3D models and imagery carry separate terms and may be non-commercial. Prefer reading source & existing adoption ledger (docs/GEV_ADOPTION.md), use REA only for shipped artifacts or behavior without source proof.

## 9. Launch acceptance gates
- 0 verified, 0 unverified: attractive and truthful area discovery, no real-looking fabricated offers.
- 0 verified, 5 authorized unverified: browseable with unmistakable label; no verified score/badge or confirmed booking.
- 3 evidence-verified: "Verified by Lodgist" only with reviewer audit, current checks and allowed publication state.
- Suspended/flagged/expired items never display as available.
- Third-party source pointer navigates out; no unauthorized asset copying or direct Lodgist booking.
- Existing WhatsApp verified-search and booking overlap tests unchanged unless explicitly updated and passed.
- Run schema validation, migrations on disposable DB only, API tests, typecheck, lint and mobile Playwright; reviewer approves evidence before merging.
- No production database changes, cloud costs, token/credential changes, scraping jobs, publication, or deploy without separate explicit approval.

## 10. Non-goals for this PR
